# QMK 매크로 문장 삽입 프로그램 설계

작성일: 2026-07-27
상태: 확정 (기술 세부는 조사 결과 반영 후 갱신)

## 1. 목적

QMK 키보드(Helix Pico 한쪽, 24키)의 키를 누르면, Windows에서 현재 포커스된 창의 커서 위치에
미리 등록해 둔 문장이 타이핑되어 들어간다. 문장은 최대 24개까지 등록하며, 프로그램 UI에서 관리한다.

해결하려는 문제: 자주 쓰는 정형 문장(주소, 계좌번호, 회신 서명, 안내 문구 등)을 매번 손으로 치거나
어딘가에서 복사해 오는 반복 작업을 물리 키 한 번으로 줄인다.

## 2. 확정된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 키보드 → PC 신호 | QMK Raw HID | 단축키 충돌이 없고, 24개를 인덱스로 깔끔히 구분. 양방향이라 확장 여지 있음 |
| 텍스트 삽입 방식 | `SendInput` 유니코드 타이핑 | 클립보드를 전혀 건드리지 않음 |
| 프로그램 형태 | 트레이 상주 + 치트시트 오버레이 | 평소 화면을 차지하지 않고, 24개를 외울 필요가 없음 |
| 하드웨어 | Helix Pico 한쪽 (4행 × 6열 = 24키) | 물리 키 24개와 문장 24개가 1:1 |
| 언어/UI | C# + .NET 8 + WPF | `WS_EX_NOACTIVATE` 등 Win32 확장 스타일 제어가 확실하고 단일 exe 배포 가능 |
| 앱 이름 | MacroTyper (가칭) | 변경 가능 |

### 2.1 명시적으로 제외한 것 (YAGNI)

- 클립보드 방식 삽입 — 유니코드 타이핑으로 결정
- 문장 내 플레이스홀더(`{date}`, `{clipboard}` 등) 치환
- 문장 프로필/그룹 전환, 클라우드 동기화, 사용 통계
- 마우스로 클릭해서 삽입하는 상시 패널 (오버레이는 보기 전용)

## 3. 아키텍처

```
[Helix Pico]
     │  Raw HID 32바이트
     ▼
 HidListener ──byte[32]──► MacroProtocol ──MacroEvent──► App (코디네이터)
 (연결/재연결/수신)         (패킷 ↔ 이벤트, 순수 함수)         │
                                                    ┌───────┼────────┐
                                                    ▼       ▼        ▼
                                              TextInjector  Overlay  Manager
                                                    │       Window   Window
                                              SlotStore        │
                                              (문장 24개)  [치트시트]
                                                    │
                                          [활성 창에 타이핑]
```

### 3.1 컴포넌트 경계

각 조각은 자기 관심사만 알고, 이웃의 내부를 모른다.

| 컴포넌트 | 책임 | 모르는 것 |
|---|---|---|
| `HidListener` | HID 장치 탐색·열기·수신·재연결 | 슬롯, 문장, 프로토콜 의미 |
| `MacroProtocol` | `byte[32]` ↔ `MacroEvent` 변환 | I/O, UI, 파일 |
| `SlotStore` | 슬롯 24개 로드·저장·검증 | HID, 삽입 방법 |
| `TextInjector` | 문자열 → `SendInput` 타이핑 | HID, 슬롯 번호, 파일 |
| `InputBuilder` | 문자열 → `INPUT[]` 배열 생성 (순수) | `SendInput` 호출 자체 |
| `OverlayWindow` | 치트시트 표시/숨김 | 삽입, HID |
| `ManagerWindow` | 슬롯 편집 UI | HID, 삽입 내부 구현 |
| `TrayIcon` | 트레이 아이콘·메뉴·상태 표시 | 나머지 전부 |
| `App` | 위 조각들을 배선 | 각 조각의 내부 |

`HidListener`가 `TextInjector`를 직접 부르지 않는 것이 핵심이다. 이 덕분에 매크로패드 없이도
가짜 `MacroEvent`를 넣어 삽입 경로 전체를 테스트할 수 있고, 반대로 삽입 없이 HID 수신만 확인할 수 있다.

`InputBuilder`를 `TextInjector`에서 분리한 이유도 같다. `SendInput`은 실제 OS 호출이라 테스트가 어렵지만,
"문자열이 주어졌을 때 어떤 `INPUT` 배열이 만들어지는가"는 순수 함수라 단위 테스트가 가능하다.
개행 처리, 서로게이트 페어 처리 같은 까다로운 규칙이 전부 여기에 모인다.

## 4. Raw HID 프로토콜

QMK Raw HID는 32바이트 고정 패킷(`RAW_EPSIZE`)을 사용하고, Usage Page `0xFF60` / Usage `0x61`로 식별된다.
그 위에 다음 4바이트 프로토콜을 얹는다. 나머지 바이트는 0으로 패딩한다.

| 바이트 | 값 | 의미 |
|---|---|---|
| `[0]` | `0xAB` | 매직 넘버. 다른 Raw HID 트래픽과 구분 |
| `[1]` | `0x01` | `Paste` — 문장 삽입 요청 |
| | `0x02` | `OverlayShow` — 치트시트 표시 |
| | `0x03` | `OverlayHide` — 치트시트 숨김 |
| | `0x10` | `Ping` (PC → 키보드) |
| | `0x11` | `Pong` (키보드 → PC) |
| `[2]` | `0`–`23` | 슬롯 인덱스 (`0x01`) / 레이어 번호 (`0x02`) |
| `[3..31]` | `0` | 패딩 |

매직 넘버가 다르거나 알 수 없는 명령 코드는 조용히 버린다. VIA/Vial 같은 다른 도구가 같은
인터페이스로 통신할 수 있기 때문이다.

**키보드는 인덱스만 보내고 문장 내용을 전혀 모른다.** 문장을 바꿔도 펌웨어를 다시 굽지 않는다.
펌웨어를 건드리는 것은 최초 1회뿐이다.

### 4.1 펌웨어 측 훅

- `process_record_user()` — 커스텀 키코드 `MACRO_01`~`MACRO_24`가 눌리면 `0x01` 패킷 전송 후 `false` 반환
- `layer_state_set_user()` — 매크로 레이어 진입/이탈 시 `0x02`/`0x03` 패킷 전송

## 5. 데이터 모델

### 5.1 슬롯

```csharp
sealed record Slot(int Index, string Label, string Text, bool AppendEnter);
```

- `Index` — 0~23 고정. 물리 키와 1:1
- `Label` — 치트시트에 표시할 짧은 이름 (예: "주소")
- `Text` — 실제로 타이핑될 전체 문장. 개행 포함 가능
- `AppendEnter` — 삽입 후 Enter 키를 한 번 더 보낼지

라벨과 문장을 나눈 이유: 24개를 문장 앞부분만 보고 구분하는 것은 실용적이지 않다.
치트시트에는 라벨만 뜬다.

### 5.2 저장

`%APPDATA%\MacroTyper\slots.json` — UTF-8 JSON, 24개 슬롯 배열.

- 저장은 임시 파일에 쓴 뒤 교체(atomic replace)한다. 저장 중 크래시로 설정이 날아가는 것을 막는다.
- 파일이 없으면 빈 슬롯 24개로 시작한다.
- 파일이 손상되어 파싱에 실패하면 `slots.corrupt-<타임스탬프>.json`으로 옮기고 기본값으로 시작한다.
  사용자 데이터를 조용히 지우지 않는다.

## 6. 화면

### 6.1 관리창

트레이 아이콘 더블클릭으로 연다. 위쪽에 4행 6열 슬롯 그리드, 아래쪽에 선택된 슬롯의 인라인 편집 영역.

- 채워진 슬롯은 라벨과 번호를 표시, 빈 슬롯은 점선 테두리
- 편집 영역: 라벨 입력, 문장 입력(여러 줄), "삽입 후 Enter" 체크박스
- **테스트 삽입 버튼** — 3초 카운트다운 후 그때 포커스된 창에 삽입한다.
  한글 IME나 특정 앱에서 깨지는지를 실사용 전에 확인하는 용도
- 헤더에 매크로패드 연결 상태 표시

### 6.2 치트시트 오버레이

매크로 레이어 키를 홀드하는 동안 화면에 뜬다.

- 4행 6열, 라벨만 표시. 빈 슬롯은 흐리게
- 반투명 어두운 패널. 활성 창이 있는 모니터 중앙
- **포커스를 절대 받지 않는다** — `WS_EX_NOACTIVATE`
- **클릭이 아래 창으로 통과한다** — `WS_EX_TRANSPARENT`
- 작업 표시줄과 Alt+Tab에 나타나지 않는다 — `WS_EX_TOOLWINDOW`
- 매번 새로 만들지 않고 하나를 재사용하며 `Visibility`만 토글한다

오버레이가 포커스를 가져가는 순간 원래 커서 위치가 날아가 프로그램 전체가 무의미해진다.
이것이 이 화면의 유일한 절대 조건이다.

## 7. 에러 처리

| 상황 | 처리 |
|---|---|
| 매크로패드 미연결 / 분리 | 트레이 아이콘 회색 + 툴팁 표시. 1초 간격 재연결 시도. 크래시하지 않음 |
| 빈 슬롯 키 눌림 | 무시. 아무 일도 일어나지 않음 |
| 알 수 없는 패킷 | 조용히 버림 |
| `SendInput` 실패 (반환값 < 요청 개수) | 로그 기록 후 중단. 부분 삽입된 상태를 되돌리지는 않음 |
| 대상 창이 관리자 권한 (UIPI 차단) | 삽입이 무시됨. 트레이 알림으로 "관리자 권한으로 재시작" 안내 |
| 설정 파일 손상 | 백업 후 기본값으로 시작 |
| 프로그램 중복 실행 | Mutex로 차단하고 기존 인스턴스의 관리창을 띄움 |

## 8. 테스트 전략

순수 로직과 OS 호출을 분리했기 때문에 다음이 실제 하드웨어 없이 테스트된다.

| 대상 | 방식 |
|---|---|
| `MacroProtocol` | 단위 테스트. 정상 패킷, 잘못된 매직, 미지의 명령 코드, 범위 밖 인덱스 |
| `InputBuilder` | 단위 테스트. 한글, 영문, 개행(`\n`/`\r\n`), 이모지(서로게이트 페어), 빈 문자열, 탭 |
| `SlotStore` | 단위 테스트. 임시 디렉토리 사용. 저장/로드 왕복, 손상 파일 복구, 없는 파일 |
| `HidListener` | 가짜 스트림 주입으로 수신 루프와 재연결 로직 검증 |
| `TextInjector` | 실제 `SendInput`은 통합 테스트 영역. 관리창의 "테스트 삽입"이 수동 검증 경로 |
| 오버레이 포커스 | 수동 검증. 메모장에 커서를 둔 채 레이어 키를 눌러 커서가 유지되는지 확인 |

## 9. 알려진 리스크

| 리스크 | 대응 |
|---|---|
| ATmega32U4 USB 엔드포인트 부족으로 `RAW_ENABLE`을 켤 수 없음 | 조사 중. Console/Mousekey 등을 끄는 것으로 해결 예상 |
| 스플릿 키보드 한쪽만 사용 시 슬레이브 폴링 지연 | 조사 중 |
| 한글 IME 조합 중 삽입 시 문자 깨짐 | 조사 중. 삽입 전 조합 확정 처리 필요 여부 확인 |
| 관리자 권한 앱에 삽입 불가 (UIPI) | 트레이 메뉴에 "관리자 권한으로 재시작" 제공 |
| 게임(DirectInput) 등 일부 앱에서 미동작 | 문서화. 이 프로그램의 대상이 아님 |
